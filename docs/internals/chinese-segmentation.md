# 中文断句依赖调研

调研日期为 2026-11-05。目标是在现有 `LanguageSegmenter` 接口内支持中文，沿用英文的字幕长度平衡和时间映射。输入包括有标点字幕，以及截图中没有标点的连续中文。

| 项目                                                                                    | 能力和接入成本                                                                                                       | 本次选择                                                     |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| [Echogarden text-segmentation](https://github.com/echogarden-project/text-segmentation) | MIT，TypeScript，支持中文句末标点和短语标点。项目已安装 0.8.1。细粒度中文分词可选装 ICU WASM，上游说明该包为 27 MB。 | 复用现有依赖处理句子和短语，关闭可选 WASM。                  |
| [segmentit](https://github.com/linonetwo/segmentit)                                     | MIT，支持浏览器的中文分词及词性标注。上游说明完整词典约 3.8 MB，可裁剪词典。没有提供无标点文本的语义句末识别。       | 会新增词典和初始化成本，本次不引入。                         |
| [jieba-wasm](https://github.com/fengkx/jieba-wasm)                                      | MIT，提供中文分词、词性和词位置，浏览器需要初始化 WASM。                                                             | 需要额外 WASM 资源及加载适配，单独分词仍需现有字幕长度算法。 |
| [SentenceX](https://github.com/wikimedia/sentencex)                                     | MIT，浏览器使用 WASM 绑定，按句末标点和语言规则分句。                                                                | 不能单独解决截图中没有句末标点的长段，也不提供字幕长度平衡。 |

这些判断来自各项目 README 和 Echogarden 源码，不是性能排名。

## 接入方案

中文和英文共用 Echogarden 适配器，分别注册到 `segmenterFor`。简体、繁体及字幕轨道的语言别名通过现有 `supportedLanguage` 归一化。平台代码只传字幕轨道语言，不读取翻译目标设置来选择断句器。

Echogarden 提供句末和短语边界。中文 Han 文本中的词边界由 Chrome 内置的 [`Intl.Segmenter`](https://github.com/tc39/proposal-intl-segmenter) 提供。该标准提供按语言划分的词、句和字素边界，返回原字符串的索引。适配器保留 UTF-16 偏移，直接复用 `fitCaptions` 的显示列宽、源 cue 边界和长度平衡。中文的源 cue 切点只有落在词边界时才参与长度平衡，避免把“气氛”切成“气”和“氛”。英文的词边界和切分方式保留。

有标点时按句末分句；超长时先考虑短语和源 cue 边界，再考虑词边界。没有标点的长段也能拆成字幕，但这不等于恢复语义句号。代码不会补标点或改写原文。规则库的句末判断也不能保证所有口语表达都符合语义。

不新增 npm 依赖、模型下载、网络请求、权限或长度参数。重叠字幕和实时 DOM 字幕继续保持完整。

## 验证范围

测试覆盖繁简体及轨道语言别名、中文引号、CRLF 与 UTF-16 偏移、无标点长段、英文和小数混排、源 cue 切分后的显示时间，以及 X 中文原文直接显示且不请求 Provider 的路径。保留日语的原样返回测试和现有英文回归测试。

## 无头浏览器对比

网页抓取最初返回 HTTP 403；随后使用无头 Chromium 153 成功播放原帖，取得语言为 zh 的 154 条字幕。

在同一浏览器中比较 Echogarden 0.8.1 加 ICU WASM 0.4.0 与原生 `Intl.Segmenter`。154 条字幕逐条处理，词文本与 UTF-16 起止位置全部一致。按插件规则拼接后的 1818 个 UTF-16 码元中，两者也都输出 987 个词且位置完全一致。另加的 11 个繁简体、人名和混排样本也相同。这是输出一致性检查，没有人工金标准，不能作为准确率。

两者都能完整识别“气氛”，也都会将简体“基金会”分为“基金 / 会”，将“马云”分为“马 / 云”。词典边界不总等于适合字幕显示的切点。本次样本没有显示出增加 ICU WASM 的质量收益，因此保留原生分词。

新隔离浏览器缺少 API 配置，原帖的插件字幕层受到 configured 检查阻挡。原帖检查证明了播放和真实字幕输入，字幕层的渲染及切换由打包扩展的浏览器回归用例验证。该用例使用原帖中跨 cue 的“气氛”文本，确认字幕已拆短、词保持完整、同语言原文显示没有 Provider 请求。

首次将三个平台的语言轨道端到端用例与全量单测并发运行时，YouTube 和 X 在本机达到 30 秒超时。停止并发后，三个用例在原超时设置下重跑通过。
