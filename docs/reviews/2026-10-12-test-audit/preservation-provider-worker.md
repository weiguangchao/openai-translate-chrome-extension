# Provider and worker preservation review

Independent review against baseline 6b1da64. This reviewer compared every deleted block in API, caption-translation, queue and playback-schedule tests with the actual keepers. It also read the API, model JSON parser, translation validator, queue and session store owners, and the changed transport deadline and token-format proof. No tests ran and no repository files changed during this review.

No deleted contract lost its remaining proof. The review found one static implementation error and one pre-existing rejection-row weakness. Root has already replaced the two missing API helper references with structuredReply. Root also repaired the missing-id row to reach ID validation. Execution results appear in the parent report.

## Findings

1. Moving resultsContent out of api.test.ts initially left two compatibility tests calling the removed helper. The errors were at the response_format and reasoning_effort batch tests. Root now imports structuredReply and supplies two explicit ID/translation results in both tests. Read-only inspection confirmed no resultsContent reference remains in API tests. Validation still belongs to root.
2. provider-responses.test.ts's row named "a result without an id" supplies the root object `{ translation: '甲' }`. The API rejects that object because it has no results array, before result ID validation. This row existed at baseline, so it is not coverage lost by pruning. Root repaired the same row to `{ results: [{ translation: '甲' }] }`. A mutation that gives a missing result ID the default zero would then fail this row. The rest of its translation is valid, so rejection reaches the named guard.

## API and protocol transfers

The four unusable-batch inputs from the deleted API table remain in the response owner. Plain text and the segments object require null and no publications. A short result list and a blank later result require null while preserving the usable first publication. The moved fenced-body test retains literal escaped Unicode, quote, newline and slash output plus exact publications. The GLM thinking-block, string-ID, text-part and reasoning_content cases retain their original inputs and expected outputs.

The migrated batch API table covers apiFormat undefined, chat and completions, requires the chat-completions URL and non-streaming request, and now also asserts callback publications for IDs 2, 0 and 1 with independent literal translations. The old legacy-publication case is therefore preserved in every migration row. Request max_tokens, reasoning_effort and response_format assertions removed from the parser-only fenced-body case remain in this API request contract. Compatibility-state tests remain separate.

All token-format input values remain. Exact token expectations are literal strings, so the test no longer generates its expected value by calling the same locale formatting method as production.
