# Subline 双语字幕

在 YouTube 和 HBO Max 上显示双语字幕。YouTube 将原文字幕断句后，使用自己的 OpenAI 兼容 API 翻译，以自定义字幕显示原文和译文；HBO 优先使用已有母语字幕。扩展使用 Chrome Manifest V3、React、TypeScript 和 Vite，无需后端。

## 安装

需要 Node.js 22.13+ 或 24+。

```sh
npm install
npm run build
```

打开 `chrome://extensions`，开启「开发者模式」，点击「加载已解压的扩展程序」，选择本项目的 `dist` 文件夹。安装或重新构建并重新加载扩展后，请刷新已打开的视频页面。扩展重载时，旧内容脚本会停止并恢复网站原字幕；刷新视频页面后重新启用双语字幕。

点击扩展图标进入设置，选择原文语言和母语后保存，再到播放器中开启对应语言的原字幕。YouTube 需要填写 Base URL、API Key，获取并选择支持文本翻译的模型；也可手动填写 Model ID。HBO 已有可读取的母语字幕时可直接加载，无需配置 API。

## 配置

| 设置     | 行为                                                                                                                                                                                                                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Base URL | 接口根地址，例如 `https://api.openai.com/v1`，保留服务商要求的版本路径                                                                                                                                                                                                                                                                                                               |
| Model ID | 首先调用 `GET /models`；仅在 404 或 405 时兼容 `GET /model`；支持手动输入                                                                                                                                                                                                                                                                                                            |
| 接口类型 | 默认 `POST /chat/completions`，高级设置中可切换至 `POST /completions`。批量请求使用 `stream: true`；chat 同时带与 completions 相同算法的 `max_tokens`。服务商对 `stream`、`reasoning_effort` 或 chat 的 `max_tokens` 返回 400/422 时，按 `stream`、`reasoning_effort`、chat 的 `max_tokens` 的顺序去掉该项，并在本次运行中记住。单句翻译不流式。`/completions` 始终保留 `max_tokens` |
| 语言     | 学习语言为原文，母语为译文；需要在播放器中手动选择相应原字幕                                                                                                                                                                                                                                                                                                                         |
| 提示词   | 内置英文提示词，让模型以专业翻译的身份忠实翻译原文；不提供编辑，旧版本保存的自定义提示词不再生效                                                                                                                                                                                                                                                                                     |
| 样式     | 分别设置原文、译文颜色和字号，调整译文背景及行间距，有实时样式预览                                                                                                                                                                                                                                                                                                                   |

更改设置后点击「保存更改」，已打开的视频页会自动应用。测试连接会发送一条示例字幕，服务商可能收费；获取模型不等于测试翻译成功。

## 字幕适配与限制

- YouTube：只读取设置中的原文语言轨道。优先使用当前选中的同语言轨道，否则优先人工字幕，再选自动生成字幕。即使视频同时提供原文和母语字幕，或播放器选中了网站自动翻译，也只下载原文并交给配置的 Provider 翻译，不加载网站已有译文，也不使用浏览器 TextTrack 的母语字幕。
- 人工字幕和自动字幕均先合并跨段的句子，再按句末标点拆开；自动字幕还使用词级时间戳和停顿。超过 90 个西文字符显示宽度的长句，由扩展在英文逗号 `,` 或中文逗号 `，` 处切开，并尽量少切：相邻分句能放进该宽度就留在同一条字幕。中日韩文字按双倍宽度计算。没有这些逗号的一整句会保持原样，即使它仍然超宽。切出的每一部分都是一条独立的字幕，有自己的起止时间，单独显示、单独翻译；Provider 不选择断点。
- 译文返回前，原文行只显示当前这条字幕，译文行显示「翻译中」。译文返回后，原文和译文按字幕条同时切换。仅有字幕 DOM、没有完整时间轴的播放器不切分，仍整句翻译。
- 切出的字幕条时间由扩展从原字幕计算，模型不生成时间戳。有词级时间戳时保留原始同步关系，没有时按文字位置估算。拖动进度后按当前位置显示。极长且无标点的连续文本按接口的 5000 字符上限组成输入窗口。
- YouTube 在原文轨道尚未就绪、下载失败或没有指定语言轨道时，不将当前 DOM 中的半句或网站译文发送给 Provider。下载失败会重试；句子时间轴就绪后开始显示自定义字幕。
- HBO 的浏览器 TextTrack 或点播字幕清单中有母语字幕时，直接加载并按译文自身的时间戳显示，不发送模型翻译或预取请求。即使译文下载失败、仍在加载或当前时间没有译文，也不会自动改用模型。支持简繁体及语言地区标签匹配，未配置 API 也能使用已有字幕。
- HBO / Max：适配 `max.com`、`hbomax.com`、`hbo.com`，当前点播播放器通过页面内的播放器状态获取 DASH 清单，提前读取原文 WebVTT 文件，合并跨 Period 的字幕并校正时间偏移，再使用与 YouTube 相同的分段预取；不必等当前字幕出现在 DOM 中。字幕关闭、语言切换、换集或扩展停用后取消旧下载并清理显示。读取失败会重试，不支持的播放器保留 TextTrack / DOM 适配。站点字幕 DOM 选择器集中在 `src/extension/captions.ts`。
- 已在登录后的 HBO Chrome 点播播放器验证字幕清单和 WebVTT 时间轴。当前适配依赖播放器页面结构，支持静态 DASH 清单中的独立 WebVTT 字幕；播放器版本、地区、直播或其他字幕封装可能需要新增适配。画布、封闭 Shadow DOM、跨域且不在授权域名内的嵌入播放器等不可读取字幕不受支持。
- 无可读字幕的视频不提供语音识别；不下载或解密视频，不处理 DRM。播放器仅提供字幕 DOM、未公开轨道列表时，无法检测其他语言的字幕，需要在播放器中选择原文语言。
- YouTube 和取得时间轴的 HBO 在字幕加载完成后立即开始预取，无需等待第一句出现。每段最多 10 条连续字幕，按段向 Provider 发送一次请求。段边界只落在句子之间：长句切出的几条字幕总在同一段，当前段放不下时整句移到下一段，所以一段可能不足 10 条；只有一句本身超过 10 条时才跨段。预取窗口是当前段里尚未结束的字幕，再加上紧接着的下一段。视频正常打开时，用当前进度往后 1 秒定位当前段，这一段和下一段同时压入队列。正常播放刚进入某一段时，立刻预加载它的下一段。中途打开或拖动进度时，同样从当前进度往后 1 秒重新计算，当前段可能不足 10 条。翻译成功的字幕按接口配置和原文缓存在扩展后台（仅内存，最多 5000 条），再次出现时直接复用，不再请求 Provider；仍在进行的相同字幕会合并为一次请求，失败或被中止的请求不会缓存。页面里另存当前视频已取得的译文，字幕到点时直接显示；刷新页面、切换视频或修改设置后，重新从扩展后台取回。浏览器回收扩展后台（空闲约 30 秒）、重启浏览器或重新加载扩展后，后台缓存清空；只改字号、颜色等显示设置不会让缓存失效。一段里的字幕由模型按顺序返回各条译文；每一条译文字符串闭合后就可以显示，不必等该段剩余句子；整段格式仍不对时，已经收下的保留，其余改为逐条请求。几条时间重叠的字幕拼成一行时没有单句时间可依，不切分，整行一起翻译。拖动进度后取消不再需要的任务，优先翻译新位置的字幕；切换视频、语言或配置时重新检测字幕并丢弃旧显示状态。
- 预加载不会暂停视频。刚开播或跳转后仍可能需要等待首句译文，模型持续响应过慢时也可能跟不上；迟到的译文不会覆盖其他字幕。HBO 仅能读取当前字幕 DOM 的播放器仍按当前字幕翻译，无法提前取得尚未公开的字幕。
- 支持播放器容器全屏。浏览器原生视频画中画或直接对 `<video>` 全屏无法显示额外的 DOM 译文。
- YouTube 使用插件自定义字幕，原文在上、译文在下，按字幕条同步切换；原生字幕层隐藏，关闭插件后恢复。两行均应用扩展的字号、颜色、背景和间距设置。HBO 的 DOM 原字幕沿用播放器自身背景，取得 WebVTT 时间轴或浏览器原生 TextTrack 时，则由扩展绘制两行字幕。

## 开发与验证

```sh
npm run dev       # 设置页浏览器预览，默认 http://localhost:5173
npm run lint      # 禁止 TypeScript 注释
npm run check     # lint 与 TypeScript 类型检查
npm test          # 接口、配置、翻译队列和字幕生命周期测试
npm run build    # 输出完整扩展到 dist/
```

TypeScript 文件禁止任何注释，包括行注释、块注释、JSDoc 和工具指令注释。规则覆盖 `.ts`、`.tsx`、`.mts`、`.cts`，包括测试文件；测试环境在 `vite.config.ts` 中配置。

浏览器预览支持设置、样式预览和真实接口测试，不会注入视频网站。预览使用 localStorage 保存非敏感设置，API Key 仅存在当前页面内存中，刷新后需重新填写。真实接口测试还受服务端 CORS 配置约束。Chrome 扩展通过后台请求，并按需请求 API 域名权限。

测试使用模拟 API 响应与字幕 DOM，不需要密钥，不产生 API 费用。它们不能替代真实平台验收。安装后建议检查 YouTube 字幕切换、拖动进度、全屏、开关、API 错误，以及登录后 HBO 的实际字幕层。

## 数据与权限

扩展把设置保存在 `chrome.storage.local`，限制为可信扩展上下文访问。API Key 不同步至 Chrome 账号，也不传给网页内容脚本；这仍是本地存储，并非加密保险库。HBO 使用已有译文时不调用模型；YouTube 始终使用模型翻译。需要模型翻译时，扩展把当前及即将播放的字幕、语言、提示词和模型配置发给用户选定的 API 服务商。预取的字幕可能因暂停、跳转或离开页面而没有播放，但已发出的请求仍可能计费。API Key 放在该服务请求的 Authorization 头中。

长句先在本地按逗号切成几条字幕，再和同一段的其他字幕合并为一次普通批量请求。模型不返回切分后的原文，也没有纠正请求。一次请求最多 10 条字幕。

没有应用后端、遥测或第三方分析脚本。API 响应错误内容不会原样展示，避免服务商回显密钥。自定义地址支持 HTTPS 和 HTTP，包括带端口的 IP 地址；首次连接时按需申请该主机的访问权限。阻止请求重定向，避免凭据被转发到另一个地址。

## 项目结构

```text
src/ui/                设置页、弹出面板、字幕预览
src/shared/            配置、接口客户端、本地存储
src/extension/         Service Worker、字幕适配、翻译队列
public/manifest.json   Chrome 扩展权限与入口
scripts/               扩展打包与本地图标生成
tests/                 API 合约与字幕行为测试
```

接口依据 [OpenAI Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 和 [Models 文档](https://developers.openai.com/api/reference/resources/models/methods/list)。`/model` 是第三方兼容回退。场景预览图片来自 [Unsplash 图片资源](https://images.unsplash.com/photo-1470770841072-f978cf4d019e)，打包在本地，不在运行时请求外部图片。
